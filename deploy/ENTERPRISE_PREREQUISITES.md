# Enterprise GCP Administrative Prerequisites (`deploy/`)

This guide lists Google Cloud Organization Policies, IAM boundaries, service-agent materialization rules, and licensing prerequisites discovered during live Hillclimbing runs (`HC-01`, `HC-02`, `HC-03`, and `HC-04`).
Customer platform, security, network, and FinOps administrators must review this checklist before running Stage 01 on hardened enterprise projects.

---

## 1. Organization and Security Administrators (IAM and Org Policies)

| Prerequisite or Org Policy | Exact Symptom if Missing | Action Before or During Stage 01 | Source |
| :--- | :--- | :--- | :--- |
| **Cold-start core APIs** (`serviceusage`, `cloudresourcemanager`, `iam`) | Terraform fails with `USER_PROJECT_DENIED` on brand-new projects when `user_project_override = true`. | Enable the three core APIs on each target project and wait `20` seconds for propagation before running `terraform apply`. | `HC-01 F2`, `HC-02 F1` |
| **Domain Restricted Sharing (`constraints/iam.allowedPolicyMemberDomains`)** | `google_billing_budget` fails HTTP `400 FAILED_PRECONDITION` (`One or more users named in the policy do not belong to a permitted customer`) when attaching `budget_alerts` Pub/Sub because Cloud Billing Budgets binds `billing-budget-alert@system.gserviceaccount.com`. | Grant a narrow Hub-project DRS exception for Cloud Billing Budgets OR set `enable_budget_pubsub_topic = false` in Stage 01 `terraform.tfvars` (omits `all_updates_rule` via dynamic block) to keep Billing Admin email alerts without Pub/Sub IAM mutation. | `HC-04 F2`, `HC-05 F1` |
| **Shielded VM Secure Boot (`constraints/compute.requireShieldedVm`)** | GKE node pool creation fails with `Secure Boot is not enabled in the shielded_instance_config field` when `--enable-shielded-nodes` is passed alone. | Always pass `--enable-shielded-nodes --shielded-secure-boot --shielded-integrity-monitoring` on GKE cluster creation (Stage 02 `lite-vm` already enables Secure Boot). | `HC-05 F2` |
| **Partner Model Garden Org Policy (`constraints/vertexai.allowedPartnerModelFeatures`)** | Enabling Anthropic Claude Opus 5.5 in Vertex AI Model Garden on `inference_project_id` is blocked by Org Policy (`allValues: DENY`). | Allow partner models on `inference_project_id` (or its parent folder) before enabling `diversity_profile: cross-vendor`. Day-1 default `cross-model` uses 1P Gemini only and needs no exception. | `HC-04 F3`, `M3.5` |
| **Compute Engine default SA without `roles/editor`** | GKE pods enter `ImagePullBackOff` with HTTP `403` pulling images from `hub_project_id` Artifact Registry. | Set `enable_gke_api = true` in Stage 01 to provision the least-privilege `<prefix>-gke-node@` SA (`roles/container.defaultNodeServiceAccount` + `roles/artifactregistry.reader`) and pass `--service-account` to `gcloud container clusters create`. | `HC-02 F4` |
| **`constraints/iam.disableCrossProjectServiceAccountUsage`** | Vertex AI Agent Engine and Cloud Run in `sandbox_project_id` reject attaching `worker@inference_project_id` with `400 INVALID_ARGUMENT: You do not have permission to act as service_account`. | Set `enable_adk_sandbox_roles = true` in Stage 01 to provision the same-project `<prefix>-adk-runtime@<sandbox_project_id>` SA with predict-only rights on `inference_project_id` and zero write rights on `sandbox_project_id`. | `HC-02 F10` |
| **Non-Owner operator spawning under `gcp_iam_check_mode=enforce`** | Non-Owner users receive HTTP `403 identity_assign_denied` or Policy Troubleshooter `UNKNOWN_INFO`. | Enable `policytroubleshooter.googleapis.com` on `hub_project_id` (automated in Stage 01), add operators to `factory_operator_members`, keep `gcp_iam_deny_unknown_policy = "fail-open"` unless org-level `roles/iam.denyReviewer` is granted (`WK-004`), and add federated non-admin users to the Scion `hub-members` group (`WK-006`). | `HC-01 F17`, `HC-02 F6`, `M2.4` |
| **Service Account OIDC callers (`lite-vm`)** | Scion rejects SA OIDC tokens with `service account project not allowed`. | Pass `oidc_allowed_gcp_projects = ["<hub_project_id>"]` in Stage 02 `lite-vm` when automated operators authenticate via SA OIDC tokens. | `HC-02 F6` |
| **Zero-PII CES and ADK Custom Roles** | Predefined `roles/ces.*` inherit `contactcenterinsights.*`, `adkSandboxDeployer` without `discoveryengine.agents.manage` triggers license errors, and `adkSandboxEvaluator` without `run.routes.invoke` gets HTTP `403` calling authenticated Cloud Run A2A services. | Use Stage 01 explicit Custom Roles (`gecxSandboxDeployer`, `gecxSandboxEvaluator`, `gecxSandboxJanitor`, `adkSandboxDeployer`, `adkSandboxEvaluator` with `run.routes.invoke`, `adkSandboxJanitor`, `vertexInferencePredict`). | `HC-01 F26/F27`, `HC-02 F12`, `HC-03 F3` |
| **Tier-B Kaizen Viewer SA (`enable_kaizen_gcp_obs = true`)** | Cloud Logging clients sending `x-goog-user-project=<sandbox_project_id>` fail HTTP `403` without `serviceUsageConsumer`, and `kaizen-analyst` cannot invoke Vertex AI under `kaizen_viewer` without predict-only rights. | Stage 01 binds `roles/monitoring.viewer`, `vertexInferencePredict`, and `roles/serviceusage.serviceUsageConsumer` on `inference_project_id`, plus `roles/logging.viewer` and `roles/serviceusage.serviceUsageConsumer` on `sandbox_project_id`, with zero write or delete rights. | `HC-04 F5`, `M5.5` |
| **Keyless GitHub Actions WIF (`enable_github_wif = true`) and Workflow Tamper Protection** | CI workflows fail to pull private `hub_project_id` Artifact Registry images or mint Sandbox Evaluator/Janitor tokens without static JSON keys. On `pull_request`, GitHub runs the PR branch copy of `.github/workflows/*.yml`, so unprotected repos allow a PR to weaken its own Verdict Gate. | Enable `enable_github_wif = true` with `github_repository` (and optional `github_repositories` for shared Hubs) in Stage 01, set the repository variables (`GCP_WIF_PROVIDER`, `ADK_EVALUATOR_SA_EMAIL`, `ADK_JANITOR_SA_EMAIL`, `ADK_SANDBOX_PROJECT_ID`, `ADK_SANDBOX_PROJECT_NUMBER`, `ADK_RUNTIME_IMAGE_DIGEST`), AND enforce GitHub Organization/Repository Rulesets with a pinned required workflow plus `CODEOWNERS` mandatory human review on `.github/**` and `.factory/**`. | `HC-03 M4.6`, `HC-04`, `costela M6` |
| **Autonomous Coordinator Privileged Boundary and Sandbox Builder Isolation** | Allowing autonomous `coordinator` -> `deployer` chains to submit Cloud Build jobs in `hub_project_id` would let a prompt-injected agent overwrite factory images in Hub AR. | Stage 01 isolates autonomous PR container builds strictly inside `sandbox_project_id` (`sandbox_builder_sa_email` + `sandbox_artifact_registry_url`, zero Hub AR write access) and scopes `release_builder` strictly to `scion_images` for human/CI Stage 03 staging. Treat `coordinator` as a privileged orchestrator principal and monitor wave FinOps caps (`8h/200/400` coordinator plus child budgets). | `HC-10`, `costela H3/L12` |
| **Corporate boot images and CMEK (`trustedImageProjects`, `restrictNonCmekServices`)** | VM creation fails when public Ubuntu images or Google-managed keys are blocked by Org Policy. | Override `boot_image` and `boot_disk_kms_key_self_link` in Stage 02 `lite-vm/variables.tf`. | `ADR-010` |

## 2. Network Administrators (Custom VPC, Shared VPC, and Filestore CSI)

| Prerequisite or Org Policy | Exact Symptom if Missing | Action Before or During Stage 01 / Stage 02 | Source |
| :--- | :--- | :--- | :--- |
| **`constraints/compute.skipDefaultNetworkCreation` (No `default` VPC)** | GKE Filestore CSI `standard-rwx` StorageClass fails with `network 'default' does not exist`. | Create a custom `StorageClass` referencing `parameters.network: <vpc_name>` (exported by Stage 01 output `vpc_name`) and set `volumeBindingMode: Immediate` so Filestore binds before the first agent launch. | `HC-02 F7` |
| **Private-nodes GKE control plane access** | `kubectl` and Helm time out when connecting to a private-nodes GKE cluster. | Enable `--enable-dns-access` or explicit Master Authorized Networks on the GKE cluster. | `HC-01 F9` |
| **No Public External IPs on Hub VM** | Org Policy `constraints/compute.vmExternalIpAccess` blocks VM creation with external IPs. | Stage 02 `lite-vm` omits `access_config` by default, routes egress via Stage 01 Cloud NAT, and connects operators via IAP TCP forwarding (`35.235.240.0/20`). | `ADR-002`, `ADR-010` |
| **In-cluster HTTPS on GKE (`hub_transport_policy`)** | Scion Kubernetes broker refuses `http://` in-cluster Hub URLs. | Terminate TLS in-cluster (Ingress, Gateway, or internal TLS Service) and mount `SCION_HUB_CA_CERT` when using a private CA. | `HC-01 F22` |

## 3. Platform and Runtime Administrators (Cloud Build, Vertex AI, and Scion)

| Prerequisite or Platform Rule | Exact Symptom if Missing | Action Required | Source |
| :--- | :--- | :--- | :--- |
| **Three-project ADC `quotaProject` routing (`hub != inf != sbx`)** | Antigravity CLI `1.5.14` (`AGY_ADC_AUTH=true`) routes Vertex AI calls to metadata `project-id` (`hub` on GKE, `sbx` on VM deployer/eval), causing `403` or `SERVICE_DISABLED`. | `parse_hub_project.py` and `bootstrap-hub-project.sh` inject `GOOGLE_CLOUD_QUOTA_PROJECT=<inference_project_id>` into harness configs and project env (`injectionMode=always`). | `HC-02 F8`, `ADR-013` |
| **Cloud Build custom SA logging and staging (`stage-release-kit.sh`, `cloudbuild-hub-gke.yaml`)** | Concurrent Release Kit rebuilds race on auto-created `<hub>_cloudbuild` buckets (`not found`). Passing `--gcs-log-dir` alongside `options.logging: CLOUD_LOGGING_ONLY` fails Cloud Build with `INVALID_ARGUMENT`. | `stage-release-kit.sh` routes `--gcs-source-staging-dir` (only, omitting `--gcs-log-dir`) to `sandbox_staging_bucket` because `cloudbuild.yaml` enforces `CLOUD_LOGGING_ONLY`. Pass `--gcs-log-dir=gs://<sandbox_staging_bucket>/cloudbuild-logs` only for upstream configs that do not set `CLOUD_LOGGING_ONLY` (such as `cloudbuild-hub-gke.yaml`). | `HC-02 F2`, `HC-03 F1`, `HC-04 F4` |
| **Scion v0.4 project-scoped overlay skill URIs** | `scion skills resolve` returns `skill not found` and `bootstrap-hub-project.sh apply` fails with HTTP `409` on second apply if the project UUID is omitted from project-scoped skill URIs. | Always resolve and attach project-scoped customer overlay skills as `skill://scion/project/<project_uuid>/<name>@<version>` (automated in `bootstrap-hub-project.sh` `do_overlay_sync`). | `HC-03 F2` |
| **ADK A2A AgentCard routing (`APP_URL` / legacy `agent.json`)** | On Cloud Run, `app/app_utils/a2a.py` defaults the served A2A card URL to `http://0.0.0.0:8000` unless `APP_URL` is set. Legacy brownfield repos running bare `adk api_server --a2a` return `404` when static `agent/agent.json` is absent. | Use the native `google-agents-cli` scaffold (`uvicorn app.fast_api_app:app`, ADR-014) which mounts `/a2a/app/.well-known/agent-card.json` dynamically with v0.3 JSON-RPC compat, and set `APP_URL=<https-service-url>` on Cloud Run. Keep static `agent/agent.json` only on legacy brownfield `adk api_server --a2a` repos. | `HC-03 F4`, `ADR-014` |
| **Agent Engine `gcp-sa-aiplatform-re` Artifact Registry reader** | First Dockerfile deploy to Vertex AI Agent Engine fails with `code 3` / `code 13` (`Reasoning Engine could not access the container image`) if `service-<sbx_num>@gcp-sa-aiplatform-re` lacks `roles/artifactregistry.reader` on the PR image repository. | Stage 01 now materializes `aiplatform.googleapis.com` service identity and binds `roles/artifactregistry.reader` on `sandbox_images` automatically for `gcp-sa-aiplatform-re`, `gcp-sa-aiplatform`, and `adk_runtime` on Attempt 1 (`HC12-F2`). Set `enable_agent_engine_re_ar_reader = true` only for legacy Hub-AR pulls. | `HC-02 F11`, `HC12-F2` |
| **Vertex AI Agent Engine reserved env vars and global-inference / regional-session split** | Passing `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_QUOTA_PROJECT`, or any `GOOGLE_CLOUD_AGENT_ENGINE_*` key in `deploymentSpec.env` fails with `400 INVALID_ARGUMENT` / `FAILED_PRECONDITION`. Setting `GOOGLE_CLOUD_LOCATION=us-central1` breaks global-only Gemini 4 models (`404 NOT_FOUND`), while passing `global` to `VertexAiSessionService` breaks sessions. | Omit reserved env vars (`GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_QUOTA_PROJECT`, `GOOGLE_CLOUD_AGENT_ENGINE_*`). Set `GOOGLE_CLOUD_LOCATION=global` for Gemini 4 model inference and non-reserved `ADK_AGENT_ENGINE_REGION=<region>` (such as `us-central1`) for regional `VertexAiSessionService` sessions. | `HC-02 F9`, `HC-10 F9`, `HC-11 F4/F5` |
| **Numeric project numbers in GCP resource names** | Discovery Engine `v1alpha` and Vertex AI `ReasoningEngine` return `projects/<project_number>/...` rather than `projects/<project_id>/...`. | Pass `--quota-project-number` / `--sandbox-project-number` (or set `SANDBOX_PROJECT_NUMBER` from Stage 01 output `sandbox_project_number`) to `ge_export.py` and `adk_sandbox_gate.py`. | `HC-02 F13` |
| **Persistent Hub storage on GKE** | Upstream `deploy/helm/scion-hub` defaults to `emptyDir` SQLite, wiping Hub state on pod restart. | Mount a `ReadWriteOnce` PersistentVolumeClaim (`scion-hub-home`) or Cloud SQL Postgres before running Stage 03 bootstrap. | `HC-01 F25`, `M5.4` |

## 4. Billing, FinOps, and Licensing Administrators

| Prerequisite | Exact Symptom if Missing | Action Required | Source |
| :--- | :--- | :--- | :--- |
| **Active Gemini Enterprise Project License and Caller Seat** | `ge_export.py register` (`Discovery Engine v1alpha agents:create`) fails with `400 FAILED_PRECONDITION: an active Gemini Enterprise license is not available` even when `adkSandboxDeployer` has all six `discoveryengine.agents.*` IAM permissions. Service accounts require an active project `licenseConfig` with `enableLicenseAutoRegister=true` (or an explicit seat via `batchUpdateUserLicenses`). | Distribute an active Gemini Enterprise `billingAccountLicenseConfig` to `sandbox_project_id` and configure `default_user_store` (or request free Argolis GE Plus project seats). Run `ge_export.py preflight` before live registration so unlicensed sandboxes export `dist/ge-export/` cleanly without burning retries. | `HC-02 F12`, `HC-12` |
| **Vertex AI Model Garden opt-in for Claude (`cross-vendor` only)** | Model Garden returns `404` or `403` when `diversity_profile: cross-vendor` is enabled without prior opt-in or when `constraints/vertexai.allowedPartnerModelFeatures` denies partner models. | Allow `constraints/vertexai.allowedPartnerModelFeatures` on `inference_project_id`, enable Claude Opus 5.5 manually in Vertex AI Model Garden, then set `harnesses.claude_model_garden_enabled: true` in `.factory/hub-project.yaml`. Day-1 default `cross-model` requires 1P Gemini only. | `ADR-006`, `HC-04 F3`, `M3.5` |
| **Inference Project Budget Alert and Kill-Switch** | Unchecked autonomous loops consume unexpected Vertex AI spend. In DRS orgs, attaching Pub/Sub fails until permitted. | Stage 01 attaches a Billing Budget Alert (`monthly_budget_usd`) on `inference_project_id` publishing to `budget_pubsub_topic` (set `enable_budget_pubsub_topic = false` under strict DRS), paired with Scion `max_turns` and `max_model_calls` hard caps (`exitCode=10`). | `ADR-002`, `HC-04 F2`, `M5.6` |
